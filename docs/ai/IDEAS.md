- [ ] **2026-06-06: Index the full document text, not just the Gemini summary.** `process_file` writes a note containing only Gemini's `summary` + `questions` + `action_items`; the extracted `text_content` goes into the prompt and the raw file is archived — neither is ever indexed. So Titan searches *summaries*, not source content: any detail, number, or quote not captured in the summary is unretrievable, and Titan's Late-Chunking/ColBERT machinery runs on impoverished input (garbage-in ceiling). Worse, `questions` and `action_items` become their own retrievable chunks via Titan's `#`/`##` header-split, polluting the knowledge index with meta-content (open TODOs and Gemini's questions surface as "hits"). Fix: put the cleaned full text into the note body that Titan indexes, and demote `summary`/`tags`/`domain` to frontmatter or a clearly separated, non-indexed header block; keep `questions`/`action_items` out of the indexed region entirely (separate companion note, `indexed: false`, or an HTML comment the chunker skips). Caveat — this is a design-intent decision: if the pipeline is meant as a *distilled* "corporate memory" (summaries only, by design), it already works as intended and this is moot; the idea applies only if full-text recall is the goal. Note the interaction with the 200k-char front-truncation (`_DEFAULT_MAX_CHARS`): full-text indexing of long docs makes that truncation lossier and may warrant chunked multi-pass handling. *Effort: Medium; prompt + note-layout change.*
